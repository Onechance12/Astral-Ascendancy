# RPG Game Systems Audit

## Purpose

Astral Ascendancy should grow beyond a match-only card game into a browser-native RPG card strategy game.

The player fantasy is:

```txt
I fought on a living world
  -> the board changed
  -> my cards learned
  -> my commander advanced
  -> my worlds developed
  -> my civilization unlocked new options
  -> the next battle feels different without becoming unfair
```

This audit connects the current systems: battle, worlds, resources, science, engineering, domain, rarity, and card collection.

## Current System Status

Strong foundations already exist:

- North star: game client, not dashboard.
- Core board: 5x5 living tactical battlefield.
- Card types: entities, anomalies, worlds, structures, attachments, science, projects.
- Resources: Resonance, Influence, materials, Affinity, Aether Shards.
- Combat math: damage schools, defense profiles, creature classes, terrain effectiveness, stat budgets.
- World loop: worlds can be cards, sectors, and domain assets.
- Science/engineering loop: battle behavior can become research and projects.
- Rarity economy: packs, crafting, duplicate combine, Memory, sidegrade philosophy.

Main missing foundation:

- RPG progression needs first-class rules.
- Card and commander leveling need boundaries.
- World advancement needs named stages and objectives.
- PvE progression and fair PvP normalization need to be designed together.
- The game needs data fields for mastery, relics, skills, evolution paths, and world levels.

## Core Interaction Map

```txt
Battle on 5x5 board
  -> entities move, attack, survive, die, evolve
  -> worlds terraform sectors and generate terrain objectives
  -> structures gather materials and defend economy
  -> field tests record meaningful actions
  -> science tracks convert repeated behavior into knowledge
  -> engineering projects convert knowledge/resources into upgrades
  -> domain worlds level and specialize
  -> commander, card, and faction mastery unlock new choices
  -> collection gains cards, variants, relics, cosmetics, and sidegrades
```

The important rule: progression should create new decisions before it creates bigger numbers.

## Battle Layer

The battle layer should remain easy to read.

Core verbs:

- Deploy
- Move
- Attack
- Build
- Attach
- Evolve
- Terraform
- Activate commander

Battle progression events should be specific and visible:

- Shielded ally survived an attack.
- Entity killed an enemy on a matching world.
- Structure produced resources while contested.
- World spread, purified, corrupted, or awakened.
- Commander gained Influence from a sector objective.
- Card completed an evolution condition.
- Field test objective advanced.

The UI should show progress as game objects:

- XP sparks fly into the card.
- World level ring fills around a sector.
- Commander path node pulses.
- Science console logs a field-test success.
- Relic socket glows when its condition is met.

## World Layer

World cards are the differentiator. They should have both match-state and long-term state.

### Match World State

In battle, a world sector can have:

- World type: Star, Organic, Machine, Verdant, Crucible, Astral, Mineral, Gas, Barren, Corrupted.
- Control: player, enemy, neutral, contested.
- Status: fortified, corrupted, sealed, ruined, hazard, portal, anomaly core.
- Structure: optional building on the sector.
- World attachment: seal, parasite, relay, relic, terraform kit.
- Resource memory: temporary material, Biomass, Ember, Data, healing memory, portal charge.

### Domain World State

Outside battle, a claimed world should have:

- Level
- XP
- Survey status
- Resource traits
- Structure slots
- Relic slots
- Science tags
- Specialization
- Campaign hazards
- Visual phase

### World Level Stages

World levels should be named and readable:

1. Surveyed
   - Basic type revealed.
   - Produces low resources.
   - One structure slot.

2. Settled
   - Resource trait chosen or discovered.
   - Basic defense online.
   - Field tests unlock.

3. Industrialized
   - Second structure slot or production bonus.
   - Engineering projects can be installed.
   - World visuals become more factional.

4. Awakened
   - Unique world passive unlocks.
   - World can affect campaign map or special PvE.
   - Rare upgrade objectives appear.

5. Ascendant
   - Signature domain asset.
   - Unlocks sidegrade cards, cosmetics, special missions, or faction campaign options.
   - Should not grant raw PvP stat dominance.

## Resource Layer

Resources need three scopes.

### Match Resources

- Resonance: turn energy for playing cards.
- Influence: board-control victory pressure.
- Temporary materials: generated by worlds/structures during the match.
- World memory: event-based counters such as Biomass memory, Ember memory, healing memory, Data, or portal charge.

### Domain Resources

- Plasma
- Biomass
- Alloy
- Ember
- Verdance
- Aether
- Data
- Crystal
- Tritium
- Relic Fragments

These build projects, level worlds, craft cards, and unlock progression systems.

### Account Resources

- Aether Shards: crafting and duplicate conversion.
- Card Memory: mastery and cosmetic unlocks.
- Faction Renown: commander/faction progression.
- Research XP: science tracks.
- Project XP: engineering builds.

Resource rule:

- Match resources create tactical choices.
- Domain resources create long-term civilization growth.
- Account resources create collection growth and fair rewards.

## RPG Advancement Layer

The RPG structure should have five advancement tracks.

### 1. Commander Level

Commander levels represent the player's faction leader advancing.

Unlocks:

- Ability variants
- PvE loadout slots
- Cosmetic aura
- Dialogue/campaign branches
- Relic slots
- Commander skill paths

Avoid:

- Permanent raw PvP stat boosts.
- Paid-only power.

### 2. Commander Skill Paths

Each commander should have three paths:

- Tactical: battle ability variants and board control.
- Domain: resource, world, and base development.
- Research: field tests, science, and prototype unlocks.

Example Solari paths:

- Dawn Vanguard: shield survival, Guardian mastery, formation defense.
- Solar Magistrate: Influence, treaties, sector control, purification.
- Starwright: reactors, Stellar Physics, Star-world development.

### 3. Card Mastery

Every card can have mastery without breaking PvP.

Mastery unlocks:

- Animated frame upgrades.
- Lore pages.
- Alternate art.
- Card-specific emotes/sounds.
- PvE modifiers.
- Sidegrade blueprint access.
- Evolution form access.

Mastery should not grant direct raw power in normalized PvP.

### 4. Evolution Paths

Evolution is card-specific progression.

Evolution should unlock forms:

- Guardian form
- Apex form
- Construct form
- Bloomform
- Masterwork form
- Echo form

Evolution forms are sidegrades:

- Change role.
- Change terrain preference.
- Add a risk/reward hook.
- Change animation and identity.

They should not be simple +2/+2 upgrades in fair PvP.

### 5. World Level

Worlds level by use:

- Win battles on that world.
- Complete field tests.
- Build and defend structures.
- Spend domain resources.
- Resolve campaign events.
- Install science or engineering projects.

World levels should unlock:

- More visual activity.
- Better resource routing.
- New campaign missions.
- Structure slots.
- World traits.
- Card sidegrade recipes.

## Science And Engineering Interaction

Science answers "what did we learn?"

Engineering answers "what can we build with it?"

Field-test examples:

- Shield 20 damage on Star worlds.
- Spawn 10 organisms from Corrupted worlds.
- Connect three Machine worlds.
- Heal 15 HP on Verdant worlds.
- Destroy five structures with Crimson cards.
- Blink entities through two Astral gates.

Progression result:

- Science XP increases.
- Project XP becomes available.
- Cards unlock evolution objectives.
- Worlds unlock specialization slots.
- Domain buildings unlock new functions.

## Rarity And RPG Progression

Rarity should affect excitement, art treatment, and complexity.

Rarity should not make paid cards unbeatable.

Suggested roles:

- Common: core RPG hooks, starter mastery, basic survey tools.
- Uncommon: faction paths and utility relics.
- Rare: build-around evolutions, world-level objectives, specialization choices.
- Holo: dramatic relics, domain projects, animated progression cards.
- Mythic: signature progression protocols and masterwork blueprints.
- Singularity: account-defining chase cards that are craftable, earnable, and mostly rule-bending instead of raw power.

Duplicate combine should feed:

- Card Memory
- animated borders
- lore scenes
- PvE modifiers
- sidegrade recipes
- faction cosmetic effects

## Fairness Rules

Free-to-play trust is core.

Rules:

- PvE can let long-term progression feel powerful.
- Campaign can use commander levels and world levels heavily.
- Ranked PvP should normalize raw stats.
- Progression in PvP should affect choices, cosmetics, and sidegrades, not simple permanent stat growth.
- Paid packs can accelerate collection, but not buy exclusive power.
- All gameplay-impacting cards must be earnable or craftable.

## Audit Findings

1. Battle and world design is strong, but progression is not yet expressed in data.
2. Science and engineering are pointed in the right direction and need event hooks from matches.
3. Worlds need a level model before domain becomes satisfying.
4. Cards need mastery/evolution families before "cards are alive" becomes mechanical.
5. Relics and skills need to become first-class card categories.
6. PvP normalization must be designed now, before progression systems create unfair incentives.
7. The next content set should seed RPG cards without making them battle-ready yet.

## Recommended Next Implementation Order

1. Add Set 004 RPG foundation cards and progression balance sheets.
2. Add card type support for Skill, Relic, and Evolution in catalog views.
3. Add TypeScript interfaces for progression records.
4. Add a local progression simulator for world XP, commander XP, and card mastery.
5. Add field-test event stubs to the 5x5 engine.
6. Add a domain/research prototype screen after the battle prototype is stable.
7. Only then make selected progression cards battle-ready.
